# 项目任务与临时事项管理工具

一款轻量级的静态网页工具，用于管理项目待办任务和临时事项，支持智能延期计算、计划外任务跟踪、文档附件归档、周期汇报和 GitHub 云端同步。

## 功能特性

### 核心功能

- **任务管理**：按项目维度管理待办任务，支持状态跟踪、多维筛选、计划调整
- **临时事项**：记录会议、紧急任务等临时事项，支持附件上传、预期事件（实操后补填）
- **延期计算**：自动计算临时事项对任务的影响，支持计划调整分段计算
- **计划外任务**：勾选「计划外」即自动生成对应的预期临时事项，与待办任务双向联动
- **项目导航**：左侧项目栏可折叠，与右侧清单筛选口径完全一致
- **周期汇报**：按日期范围统计完成/新增/暂停/未完成四类记录，可复制 Markdown
- **文档附件**：基于 File System Access API，附件自动归档到本地指定路径
- **数据导入导出**：支持 CSV/JSON 格式的批量导入和数据备份
- **GitHub 同步**：多设备同步，冲突时可先看差异再决定采纳哪一边
- **全局撤回**：删除类操作可一键撤销（限本次会话内）
- **操作反馈**：所有增删改操作均有 Toast 提示，无需依赖弹窗确认
- **键盘快捷键**：弹窗内按 **回车**直接执行主操作（保存/确认/确认调整…），Escape 关闭弹窗

### 延期计算规则

公式：`offset = ceil(hours / 8)`，每 8 小时算 1 个工作日，不足 1 天按 1 天算（向上取整）。

| 累计时长 | 延期工作日 | 计算方式 |
|---------|-----------|---------|
| 1小时 | 1天 | ceil(1/8) = 1 |
| 8小时 | 1天 | ceil(8/8) = 1 |
| 9小时 | 2天 | ceil(9/8) = 2 |
| 16小时 | 2天 | ceil(16/8) = 2 |
| 17小时 | 3天 | ceil(17/8) = 3 |

- 自动跳过周末和法定节假日
- 支持调休工作日识别
- 节假日数据自动更新（来源：[holiday-cn](https://github.com/NateScarlet/holiday-cn)）

## 使用说明

### 任务管理

1. 点击「新建任务」添加任务，或在项目分组标题旁点「＋」为该项目快速新建
2. 填写项目号、项目名称（可选）、任务名称、时间等信息
3. 输入已知项目号时自动识别并填入项目名称
4. 在列表中查看任务状态和延期情况
5. 使用搜索框与筛选条（项目 / 状态 / 属性 / 隐藏已完成项目）快速过滤

> **项目名称按项目号共享**：修改任意一个任务的项目名称，同项目下所有任务会一并同步，
> 避免同一项目出现两种名称写法。

### 左侧项目导航

- 侧栏列出所有项目，可拖拽调整顺序（顺序会被持久化），点击即可定位到对应任务
- 侧栏**筛选口径与右侧清单完全一致**：当前筛选下不展示的项目，导航里同步隐藏
- 序号沿用**总顺序**，不随筛选重新编号
- 右侧数字为「**未完成/总数**」，例如 `6/9`
- 侧栏右边缘的把手可折叠／展开，折叠状态会被记住，**刷新页面不会闪烁**

### 计划外任务

在新建或编辑任务时勾选「**计划外**」：

- 任务名后显示橙色「计划外」标签
- 自动生成一条对应的**预期临时事项**（描述形如 `[计划外] 18P003-Z06 青海弗迪 燃气 水电气点位图`），
  在临时事项列表中显示为「预期事件」；实操前不会产生延期，填写的时长只作「预计」显示
- 任务旁临时事项的「计划外」标签**可点击跳转到对应待办任务**
- 取消勾选后，任务不再标记为计划外，对应临时事项标签变为灰色「**计划已调整**」（记录保留，不删除）
- 完成计划外任务时，完成弹窗会提示「📝 补填临时事项实操数据」，
  点击后**直接打开临时事项的编辑窗口**补填；保存后该事项自动转为「已发生」并按实际时长顺延任务完成时间，
  随后自动回到完成弹窗继续完成流程
- 反向也成立：直接编辑那条计划外临时事项，**取消勾选「预期事件」**并保存，即转为实际事项，
  并同步更新待办任务的状态与完成时间

### 计划调整

1. 点击任务表格最后一列的「延期」按钮
2. 在弹出的延期时间线中点击「计划调整」
3. 设定新的目标完成日期
4. 系统会自动以新日期为基准重新分段计算后续延期

### 创建临时事项

1. 切换到「临时事项」标签
2. 点击「新建临时事项」；若这件事还没实操，勾选弹窗标题栏的「预期事件」，实操后再补填日期与时长

> 「预期事件」不会因为填了日期和时长就自动转正——它始终按你勾选的状态保存，
> 需要转为实际发生请**手动取消勾选「预期事件」再保存**。
3. 填写事项日期、时长（小时/天）
4. 选择影响范围：
   - **所有未完成任务**：自动影响所有未完成任务
   - **指定任务**：手动选择受影响的任务
5. （可选）拖拽或点击选择附件文件，保存后自动存入本地存档

> 延期时长由系统根据「时长」自动计算，无需额外填写。附件功能需先在「数据管理」中设置存档路径。
>
> 临时事项列表中的 ID 列截取前8位显示，悬浮可查看完整 UUID，点击可复制。影响任务超过3个时自动折叠，点击「+N个」展开。

### 周期汇报

切换到「审阅」标签 → 「周期汇报」：

- 选择日期范围（支持本周/上周/本月/上月快捷范围），改日期即时刷新
- 四类记录可分别勾选，取消勾选即不计入汇报，页面明细、统计卡片与复制出的 Markdown 三处口径始终一致：

| 勾选项 | 包含的记录 |
|--------|-----------|
| **已完成** | 任务完成、临时事项 |
| **新增** | 新建任务（当天新建并完成的会合并成一条，带「🆕 新建 + ✅ 当日完成」两个标签） |
| **暂停 / 启动** | 暂停、启动 |
| **未完成** | 计划调整、状态变更、交付件更新、预期事项 |

- 点「复制 Markdown」把汇报内容复制到剪贴板，便于粘贴进日报/周报

> 「新建」记录依赖任务的创建时间，仅对开启该记录功能之后新建的任务生效。

### 查看延期影响

1. 切换到「审阅」标签
2. 点击任务的「延期记录」链接
3. 查看影响该任务的所有临时事项

### 数据导入

#### CSV 格式

```csv
项目号,项目名称,任务名称,开始时间,计划完成时间,状态
PRJ-001,,需求分析,2024-06-01,2024-06-15,未开始
PRJ-001,需求管理平台,前端开发,2024-06-10,2024-06-25,进行中
```

> CSV 支持多种分隔符（逗号、Tab、分号、竖线），自动识别。日期支持 `2024-06-01`、`2024/06/01`、`2024.06.01`、`2024年06月01日`、`06/01/2024`、`01.06.2024` 等格式。

#### JSON 格式

```json
[
  {
    "projectName": "PRJ-001",
    "projectTitle": "需求管理平台",
    "taskName": "需求分析",
    "startDate": "2024-06-01",
    "plannedEndDate": "2024-06-15",
    "status": "未开始"
  }
]
```

#### 导入模式

导入 JSON 备份数据时，系统会提示选择导入模式：

- **覆盖导入**（点击「确定」）：清除当前所有数据，替换为导入的数据
- **合并导入**（点击「取消」）：保留当前数据，将导入的数据中 ID 不重复的部分追加进来

#### 复制任务为 CSV

编辑任务时，弹窗标题栏有「复制 CSV」按钮，一键把该任务复制成 CSV（字段顺序与导入格式一致），
可直接粘贴进 Excel，也能原样粘回「批量导入」的粘贴框再导入。

## GitHub 云端同步

在「数据管理」中配置仓库与 Token 后，可开启多设备同步。

| 按钮 | 作用 |
|------|------|
| ⬆ 上传到 GitHub | 正常上传；若远端已被其他设备改动（sha 不一致）会**拒绝覆盖**并提示冲突 |
| ⬇ 从 GitHub 拉取 | 用云端数据覆盖本地 |
| 🔍 对比云端差异 | 逐项比对本地与云端：本地新增 / 云端独有 / 内容差异（列出具体变化字段） |
| ⚠ 强制覆盖上传 | 用本地数据强制覆盖远端（先二次确认，无法自动恢复） |
| 🧹 清理远端多余附件 | 删除「远端有、本地已删除」而残留在仓库里的附件文件 |

**冲突处理建议流程**：先「对比云端差异」看清改了什么，再二选一——采纳云端（拉取）或以本地为准（强制覆盖）。

> 自动静默同步遇到冲突时**只会暂停、不会自动覆盖**，覆盖动作永远需要手动确认。

## 技术特点

- **零依赖**：纯原生 HTML/CSS/JavaScript，无任何第三方库
- **单文件部署**：整个应用在一个 HTML 文件中

## 数据备份

### 文档附件存档

1. 切换到「数据管理」标签
2. 在「文档附件存档」卡片中点击「设置路径」
3. 选择本地文件夹作为存档根目录
4. 之后创建临时事项时即可添加附件，自动归档到 `{日期}_{ID}/` 子文件夹
5. 更换存档路径后，需手动将旧路径下的文件迁移到新路径

### 导出数据

1. 切换到「数据管理」标签
2. 点击「导出数据 (JSON)」
3. 保存下载的 JSON 文件

### 导入数据

1. 切换到「数据管理」标签
2. 点击「导入数据 (JSON)」
3. 选择之前导出的 JSON 文件

## 常见问题

### Q: 数据会丢失吗？

A: 数据存储在浏览器 localStorage 中，清除浏览器数据会导致丢失。建议定期导出备份，或开启 GitHub 同步。

### Q: 删除的东西能撤销吗？

A: 可以。删除任务/临时事项/交付件/计划调整后会弹出带「撤回」按钮的提示，顶栏也有常驻的「↩ 撤回」按钮。
注意：撤回仅在本次会话内有效（刷新后撤回栈清空），且磁盘上的附件文件删除后无法恢复，撤回只还原数据引用。

### Q: 附件存在哪里？

A: 附件文件存储在用户指定的本地文件夹（通过「数据管理」→「文档附件存档」设置）。每次新建临时事项保存附件时，系统会在存档目录下自动创建 `{日期}_{事项ID}/` 子文件夹存放文件。更换存档路径后旧附件需手动迁移。

### Q: 附件需要什么浏览器？

A: 需要使用支持 File System Access API 的浏览器（Chrome 86+ / Edge 86+）。Firefox 暂不完全支持。

### Q: 能多人使用吗？

A: 当前版本为单机版，数据存储在本地浏览器；开启 GitHub 同步后可实现多设备间的手动同步。如需实时多人协作，需要接入后端服务。

### Q: 节假日数据准确吗？

A: 节假日数据来源于 [NateScarlet/holiday-cn](https://github.com/NateScarlet/holiday-cn)，自动从国务院公告抓取。2024-2026年数据准确，2027年以后为预估数据。

### Q: 如何修改延期计算规则？

A: 修改 `index.html` 中的 `hoursToWorkingDaysOffset` 函数即可。
